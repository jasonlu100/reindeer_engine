项目与场景

一个 项目 就是一个文件夹，里面必须有一个 project.reindeer 配置文件，记录项目名称、主场景、运行后端、窗口尺寸、物理后端以及输入映射等。引擎通过它来识别“这是一个 Reindeer 项目”。

project.reindeer（完整示例）

{
  "name": "我的游戏",
  "main_scene": "scenes/main.reindeer.tscn",
  "run_backend": "pyside6",
  "window_size": [960, 540],
  "physics_backend": "builtin",
  "input_map": {
    "ui_left":   ["Key_Left", "Key_A"],
    "ui_right":  ["Key_Right", "Key_D"],
    "ui_up":     ["Key_Up", "Key_W"],
    "ui_down":   ["Key_Down", "Key_S"],
    "ui_accept": ["Key_Enter", "Key_Return", "Key_Space"],
    "ui_cancel": ["Key_Escape"],
    "ui_jump":   ["Key_Space"],
    "ui_run":    ["Key_Shift"],
    "fire":      ["Key_J"],
    "interact":  ["Key_E"]
  }
}
旧版本的项目文件（没有 input_map、或字段类型写错）在打开时会自动修复：引擎会补齐缺失字段、把错误类型纠正为默认值，并把修正后的文件写回磁盘，因此永远不会因为配置结构不对而崩溃。

场景（Scene） 是游戏内容的容器，保存为 .reindeer.tscn 文件。一个项目可以有多个场景，但要把其中一个设为 主场景（Main Scene），运行 / 打包时才会从这个场景启动。

  • 新建场景：菜单 文件 → 新建场景，会得到一个空白的未保存场景，第一次保存时弹出“场景另存为”。
  • 设为入口：选中场景后点击 场景 → 设为主场景。
  • 运行：点击工具栏的 ▶ 运行（或 场景 → 运行）。

自定义输入映射（Input Map）

与其在脚本里硬编码按键，不如把“动作”和“按键”解耦：你定义一个动作（例如 move_left、jump、fire），再把若干按键绑到它上面。这样改键只改配置，不用动脚本。

在哪里设置

菜单 设置 → 项目设置 → 输入映射。左侧是动作列表，右侧是选中动作的按键列表：

  • 添加动作：输入动作名（建议用小写 + 下划线，如 move_left）。
  • 删除动作：移除整条动作。
  • 添加按键：点击后会弹出一个“请按下要绑定的按键…”的窗口，按下任意键即可绑定（例如 A、空格、方向键）。
  • 删除按键：把某个绑定从动作上移除。
内置动作 ui_left / ui_right / ui_up / ui_down / ui_accept / ui_cancel / ui_jump / ui_run 默认始终存在（可在编辑器里覆盖它们的按键，但不能删除）。你新增的自定义动作会和他们并列。

在脚本里使用

无论动作来自内置还是你在输入映射里自定义，都用同一组 API 查询状态：

def _physics_process(self, dt):
    # 移动：动作名就是你设置的字符串
    if self.is_action_pressed("move_left"):
        self.set_position(self.get_position() + self.Vector2(-200 * dt, 0))
    if self.is_action_just_pressed("jump"):
        self.velocity_y = -500
    if self.is_action_pressed("fire"):
        self.shoot()

常用查询函数：is_action_pressed（按住期间为 True）、is_action_just_pressed（按下当帧为 True）、is_action_just_released（松开当帧为 True）。它们都能正确识别绑在该动作上的任意一个按键。

它在文件里的样子

输入映射就是 project.reindeer 里的 input_map 字段（见上方完整示例）。键名使用 Qt 风格的名字，如 Key_A、Key_Space、Key_Left。如果你手动编辑这个文件，格式不对也没关系——打开项目时会被自动修复。
